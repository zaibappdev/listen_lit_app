# Contributing

Thanks for considering a contribution to Listen Lit.

1. Open an issue for larger changes so the scope can be discussed first.
2. Keep changes focused and follow the existing Flutter/Provider structure.
3. Do not commit API credentials, user data, signing files, or unlicensed music.
4. Add or update tests for behavior changes.
5. Before opening a pull request, run:

   ```sh
   dart format .
   flutter analyze
   flutter test
   ```

Include a concise summary, test results, and screenshots for visible UI changes.
